# Paperclip — приложение для управления работой ИИ-агентов.

Оркестрация команд ИИ-агентов с открытым исходным кодом.

**Если OpenClaw — это _сотрудник_, то Paperclip — _компания_.**

Paperclip — сервер на Node.js и интерфейс на React, которые координируют команду ИИ-агентов для ведения бизнеса. Подключайте своих агентов, ставьте цели и отслеживайте работу и расходы в одной панели. Выбирайте модели и инструменты агентов (harness), сохраняя задачи, навыки, права и историю команды в одном месте.

Внешне это менеджер задач. Внутри — организационная структура, бюджеты, правила управления, связь работы с целями и координация агентов.

**Управляйте целями бизнеса, а не пул-реквестами.**

|        | Шаг | Пример |
| ------ | --------------- | ------------------------------------------------------------------ |
| **01** | Определите цель | _«Создать лучшее ИИ-приложение для заметок и довести его ежемесячную регулярную выручку (MRR) до $1 млн»._ |
| **02** | Соберите команду | CEO, CTO, разработчики, дизайнеры, маркетологи — любые боты и провайдеры. |
| **03** | Согласуйте и запустите | Проверьте стратегию. Задайте бюджеты. Запустите работу. Следите за ней в панели управления. |

## Paperclip подойдёт вам, если

- ✅ Вы хотите создавать **автономные ИИ-организации**
- ✅ Вы **координируете разных агентов** (OpenClaw, Codex, Claude, Cursor) ради общей цели
- ✅ У вас открыты **20 терминалов Claude Code одновременно**, и вы теряете нить того, кто чем занят
- ✅ Вы хотите, чтобы агенты работали **автономно круглосуточно**, сохраняя возможность проверять работу и вмешиваться при необходимости
- ✅ Вы хотите **отслеживать расходы** и соблюдать бюджеты
- ✅ Вам нужен процесс управления агентами, **похожий на работу с менеджером задач**
- ✅ Вы хотите управлять своими автономными бизнесами **с телефона**

## Четыре основы

Чтобы организация ИИ-агентов приносила результат, должны работать четыре составляющие: задачи, организация, обучение и инфраструктура. Именно на них построен Paperclip.

## Какие проблемы решает Paperclip

| Без Paperclip | С Paperclip |
| ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ У вас открыты 20 вкладок Claude Code, и вы не можете уследить, кто что делает. После перезагрузки всё теряется. | ✅ Работа оформлена задачами, обсуждения собраны в цепочки, а сессии сохраняются после перезагрузки. |
| ❌ Вы вручную собираете контекст из разных мест, чтобы напомнить боту, над чем вы работаете. | ✅ Контекст связан с задачей, проектом и целями организации — агент знает, что делать и зачем. |
| ❌ Папки с конфигурациями агентов не упорядочены, и вы заново создаёте управление задачами, общение и координацию агентов. | ✅ Paperclip сразу даёт оргструктуру, задачи, делегирование и правила управления — чтобы вы управляли компанией, а не набором скриптов. |
| ❌ Бесконечные циклы тратят сотни долларов на токены и исчерпывают квоту ещё до того, как вы заметите проблему. | ✅ Учёт затрат, предупреждения о бюджете и автоматические паузы помогают контролировать стоимость работы. |
| ❌ У вас есть повторяющаяся работа: поддержка клиентов, соцсети, отчёты. Приходится помнить, что её нужно запустить вручную. | ✅ Регулярные задания создают назначенные задачи по расписанию; результаты и историю запусков можно проверить. |
| ❌ Появилась идея — нужно найти репозиторий, запустить Claude Code, держать вкладку открытой и постоянно за ней следить. | ✅ Добавьте задачу в Paperclip. Агент-разработчик работает над ней до завершения, а руководитель проверяет результат. |

## Что отличает Paperclip

Paperclip берёт на себя сложные детали оркестрации.

|                                   |                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Атомарное взятие задачи в работу.** | Единственный исполнитель и блокировки выполнения не дают конкурирующим запускам одновременно забрать одну задачу. |
| **Сохранение рабочего контекста.** | Задачи, комментарии и документы остаются в Paperclip. Адаптеры с соответствующей поддержкой возобновляют сохранённые сессии между запусками. |
| **Подключение навыков при выполнении.** | Агенты могут получать рабочие инструкции Paperclip и контекст проекта во время запуска, без переобучения. |
| **Правила управления с откатом.** | Обязательные согласования соблюдаются, изменения конфигурации сохраняются по версиям, а неудачные изменения можно безопасно откатить. |
| **Подконтрольные подключения.** | Доступ людей, допуск агентов и разрешения на действия шлюза настраиваются отдельно. Разрешите вызов однократно или сохраните правило, которое можно отозвать. |
| **Выполнение с учётом целей.** | Связанные задачи и проекты содержат иерархию целей: агенты видят не только название, но и смысл работы. |
| **Переносимые шаблоны организаций.** | Экспортируйте и импортируйте организации, агентов и навыки с удалением секретов и обработкой конфликтов. |
| **Изоляция организаций.** | Проверки доступа в пределах организации разделяют работу, агентов и историю действий разных организаций в одной установке. |

### Подсистемы

<table>
<tr>
<td width="50%">

**Учётные записи и доступ** — Два режима развёртывания: доверенный локальный или с аутентификацией. Роли и права людей, API-ключи агентов, короткоживущие JWT запусков, участие в организациях и приглашения. Связь работы с ответственным пользователем сохраняется при делегировании и использовании поддерживаемых управляемых подключений.

</td>
<td width="50%">

**Оргструктура и агенты** — У агентов есть роли, должности, подчинённость, права и бюджеты. Примеры адаптеров показаны на схеме: Claude Code, Codex, CLI-агенты вроде Cursor/Gemini/bash, боты с HTTP и вебхуками вроде OpenClaw, а также внешние плагины адаптеров. Если агент умеет получать heartbeat, он принят на работу.

</td>
</tr>
<tr>
<td>

**Работа и задачи** — Задачи связаны с организацией, проектом, целью и родительской задачей. Есть атомарное взятие в работу с блокировками выполнения, явные блокирующие зависимости, комментарии, документы, вложения, результаты работы, метки и состояние во входящих. Ищите по задачам, просматривайте версии документов и оставляйте комментарии к конкретным фрагментам.

</td>
<td>

**Выполнение по heartbeat** — Очередь сигналов запуска в базе данных с объединением повторных сигналов, проверкой бюджета, выбором рабочего пространства, передачей секретов, загрузкой навыков и вызовом адаптера. Запуски создают журналы, записи об использовании ресурсов и состояние сессии в формате адаптера. Восстановление с заданными ограничениями обрабатывает поддерживаемые сбои и показывает случаи, в которых необходимо участие человека.

</td>
</tr>

<td>

**Рабочие пространства и исполнение** — Репозитории и рабочие пространства проектов, необязательные изолированные пространства выполнения (git worktree, ветки оператора) и сервисы среды выполнения (серверы разработки, URL для предпросмотра). Провайдеры песочниц позволяют выполнять работу за пределами локального компьютера; доступность зависит от настроенной среды и адаптера.

</td>
<td>

Настроенные проверки задач определяют порядок завершения работы; согласования действий подключений управляют вызовами через шлюз инструментов.

</td>
</tr>
<tr>
<td>

**Бюджеты и контроль затрат** — Учёт токенов и расходов по организации, агенту, проекту, цели, задаче, провайдеру и модели. Бюджетные политики для отдельных областей с порогами предупреждений и жёсткими ограничениями. Ограничения применяются по учтённым расходам; задержка отчётности об использовании и уже выполняемая работа могут отсрочить остановку.

</td>
<td>

Каждое выполнение регулярного задания создаёт отслеживаемую задачу и запускает назначенного агента — вручную запускать работу не нужно.

Расширяйте Paperclip без создания форка.

</td>

Значения секретов, на которые ссылается пакет, не включаются; перед передачей проверяйте пакет, поскольку обычные значения переменных окружения и локальные пути могут сохраниться. Пакеты переносят конфигурацию организации; для полного восстановления экземпляра нужны резервные копии.

## Чем Paperclip не является

|                              |                                                                                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Не просто чат-бот.** | Обсуждения привязаны к задачам, планам, решениям и результатам. Экспериментальный Agent Chat умеет передавать работу в назначенные задачи. |
| **Не фреймворк агентов.** | Мы не определяем, как создавать агентов. Мы помогаем управлять компанией, состоящей из них. |
| **Не просто конструктор рабочих процессов.** | Регулярные задания выполняются в организации с ролями, целями, бюджетами и правилами управления. |
| **Не менеджер промптов.** | Агенты используют собственные промпты, модели и среды исполнения. Paperclip управляет организацией, в которой они работают. |
| **Не ограничен одним агентом.** | Начните с одного агента и вырастите команду с общими навыками, делегированием и проверками. |
| **Не только для проверки кода.** | Разработка и проверка пул-реквестов соседствуют с исследованиями, эксплуатацией, подготовкой контента и другой работой. |

## Быстрый старт

Открытый исходный код. Развёртывание на своём сервере. Учётная запись Paperclip Cloud не нужна.

### Предварительная русская версия из исходного кода

> **Предварительная версия:** ветка `codex/russian-task-views` содержит расширенную русскую локализацию, предложенную в [PR #5](https://github.com/dexogen/paperclip/pull/5). Команды ниже выбирают эту ветку явно, поскольку изменения ещё не приняты в `master` форка. Используйте эту версию для ознакомления и проверки; актуальные результаты проверок и состояние слияния доступны в PR. Это не выпуск полностью переведённого приложения.

Потребуются **Node.js 24.11+**, **pnpm 9.15.4** и Rust. Версия Rust закреплена в [файле набора инструментов Runner](packages/paperclip-runner/rust-toolchain.toml); в этой ревизии это **1.97.1**. Для сборки нужны также инструменты C; в Debian/Ubuntu это пакеты `gcc`, `libc6-dev` и `pkg-config`. Сборка нативного Runner при первом запуске может занять заметное время. Запускайте приложение от обычного пользователя ОС: встроенный PostgreSQL не запускается от `root`.

```bash
git clone --branch codex/russian-task-views https://github.com/dexogen/paperclip.git paperclip-ru
cd paperclip-ru
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://localhost:3100`. Сервер использует доверенный локальный режим с доступом через loopback; встроенная база PostgreSQL создаётся автоматически. Это запуск из исходного кода для локальной работы, без установки системного сервиса. Для доступа через сеть настройте [режим с аутентификацией](doc/DEPLOYMENT-MODES.md).

В русской сборке интерфейс по умолчанию открывается на русском. Переключатель «Язык / Language» позволяет выбрать русский или английский; выбор сохраняется в текущем браузере, в том числе между перезапусками. Перевод пока охватывает отдельные сценарии: первый запуск и настройку первого агента, вход и доступ к экземпляру, общие настройки и связанные формы подключения ИИ-сервисов. Остальные экраны могут содержать английский текст. Имена, введённый текст, команды, идентификаторы моделей и сообщения внешних провайдеров сохраняются без перевода.

### Официальный Paperclip

Следующие способы устанавливают официальный Paperclip из npm или репозитория `paperclipai/paperclip`. Они не устанавливают русскую версию этого форка. Настройка первого агента описана в [пошаговом руководстве](https://docs.paperclip.ing/guides/getting-started/five-minute-path/).

#### Установка с помощью агента

Передайте агенту [руководство по установке](https://docs.paperclip.ing/reference/cli/installation/).

#### Самостоятельная установка

Потребуется **Node.js версии 24.11 или новее**:

```bash
npx paperclipai@latest onboard --yes
```

CLI запускается из кеша npm; конфигурация и данные экземпляра сохраняются локально.

В [руководстве по установке](https://docs.paperclip.ing/reference/cli/installation/) описаны управляемая установка, закрепление версий, установка canary-сборок и версий по Git-ссылке, обновление, откат, управление сервисом и удаление.

Для изолированного экземпляра для ручного тестирования, в котором уже настроен агент CEO,
используйте `test-drive`. Команда работает в текущем терминале, не устанавливает системный сервис
и не создаёт первую задачу, а браузер открывает только после успешной настройки:

```bash
ANTHROPIC_API_KEY=... npx paperclipai test-drive
OPENAI_API_KEY=... npx paperclipai test-drive --harness codex
OPENROUTER_API_KEY=... npx paperclipai test-drive \
  --harness opencode \
  --model openrouter/anthropic/claude-sonnet-4.5
```

Каждый запуск без `--data-dir` создаёт отдельный временный каталог, который сохраняется после завершения;
его абсолютный путь выводится при запуске. Передайте `--data-dir`, чтобы использовать существующий каталог,
или `--no-browser`, чтобы не открывать настроенный экземпляр в браузере. При вызове из
связанного Git worktree команда `test-drive` также разрешает выполнение задач в этом worktree.
Подробнее об учётных данных и повторном использовании экземпляра —
в [руководстве по test-drive](https://docs.paperclip.ing/reference/cli/test-drive/).

> **Решение проблем: частный реестр npm в `.npmrc`**
>
> Если команда завершается ошибкой `E404` для `paperclipai` или похожей ошибкой, а в глобальном `~/.npmrc` у вас настроен частный реестр npm, например GitHub Packages, то `npx` может искать `paperclipai` в этом реестре вместо публичного реестра npm.
>
> Диагностика:
>
> ```bash
> npm config get registry
> ```
>
> Обходной способ для любой ОС: явно указать публичный реестр npm для этой команды:
>
> ```bash
> npx --registry https://registry.npmjs.org paperclipai@latest onboard --yes
> ```

Для быстрого первого запуска этот способ установки по умолчанию использует доверенный локальный режим с привязкой к loopback. Чтобы запустить Paperclip в режиме с аутентификацией и доступом через частную сеть, явно выберите вариант привязки:

```bash
npx paperclipai@latest onboard --yes --bind lan
# или:
npx paperclipai@latest onboard --yes --bind tailnet
```

Если Paperclip уже настроен, повторный запуск `onboard` сохраняет существующую конфигурацию. Для изменения настроек используйте `npx paperclipai configure`.

Или запустите официальный исходный код:

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

Интерфейс и API будут доступны по адресу `http://localhost:3100`. Встроенная база данных PostgreSQL создаётся автоматически, отдельная настройка не требуется.

> **Требования:** Node.js 24.11+, pnpm 9.15+

Для локального входа по подписке Claude или Codex на компьютере с Paperclip также нужны Python 3
и CLI соответствующего провайдера. Образ Docker уже включает их.

При разработке из исходного кода также собирается нативный Paperclip Runner, если он включён (по умолчанию для самостоятельного развёртывания). Установите набор инструментов Rust или укажите путь к совместимому готовому Runner в `PAPERCLIP_RUNNER_BINARY`.

## Частые вопросы

**В: Этот проект поддерживается или это просто очередная ИИ-поделка?**

**О:** Paperclip поддерживает [команда Paperclip](https://paperclip.ing). В исходный проект принято [более 2700 пул-реквестов](https://github.com/paperclipai/paperclip/pulls?q=is%3Apr+is%3Amerged).

<br/>

**В: Как выглядит обычная установка?**

**О:** Локально один процесс Node.js управляет встроенной базой Postgres и локальным файловым хранилищем. Для промышленной эксплуатации подключите собственный Postgres и выберите удобный способ развёртывания. Настройте проекты, агентов и цели — остальным займутся агенты.

Для удалённого доступа используйте режим с аутентификацией и привязкой к частной сети, например Tailscale, либо разверните постоянно работающий сервер с Docker. См. [режимы развёртывания](https://docs.paperclip.ing/reference/deploy/deployment-modes/) и [руководство по Docker](https://docs.paperclip.ing/reference/deploy/docker/).

<br/>

**В: Можно ли управлять несколькими организациями?**

**О:** Да. Одна установка может обслуживать несколько организаций с разделением данных и проверками доступа в пределах каждой организации.

<br/>

**В: Чем Paperclip отличается от агентов вроде OpenClaw или Claude Code?**

**О:** Paperclip _использует_ этих агентов. Он объединяет их в компанию — с оргструктурой, бюджетами, целями, правилами управления и ответственностью за результат.

<br/>

**В: Зачем нужен Paperclip, если можно просто подключить OpenClaw к Asana или Trello?**

**О:** В оркестрации агентов есть тонкости: нужно координировать взятие задач в работу, сохранять сессии, следить за расходами и устанавливать правила управления. Paperclip делает это за вас.

(Подключение внешних систем задач есть в плане развития.)

<br/>

**В: Агенты работают непрерывно?**

**О:** Агенты запускаются при назначении работы и получении новых сообщений. Необязательные heartbeat по таймеру позволяют периодически проверять наличие работы; регулярные задания создают повторяющиеся задачи по собственным расписаниям. Можно также подключить агентов, работающих вне Paperclip, например OpenClaw. Само по себе упоминание не назначает задачу и не запускает другого агента.

<br/>

## Разработка

```bash
pnpm dev              # Полная среда разработки: API + UI, отслеживание изменений
pnpm dev:once         # Полная среда разработки без отслеживания изменений
pnpm dev:server       # Только сервер
pnpm dev:mobile       # Готовый UI на :3101 для телефонов и планшетов; /api проксируется на :3100
pnpm dev:both         # Совместный запуск `pnpm dev` и `pnpm dev:mobile`
pnpm build            # Полная сборка
pnpm typecheck        # Проверка типов
pnpm test             # Быстрая проверка по умолчанию: только Vitest
pnpm test:watch       # Vitest с отслеживанием изменений
pnpm test:e2e         # Браузерные тесты Playwright
pnpm db:generate      # Создать миграцию базы данных
pnpm db:migrate       # Применить миграции
```

`pnpm test` не запускает Playwright. Браузерные наборы тестов запускаются отдельно — обычно при изменении соответствующих сценариев или в CI.

Полное руководство по разработке находится в [doc/DEVELOPING.md](doc/DEVELOPING.md).

## Наблюдаемость

Paperclip поддерживает автоматическую инструментацию сервера через OpenTelemetry по выбору пользователя — только трассировки. Она включается при заданной `OTEL_EXPORTER_OTLP_ENDPOINT` и поддерживает `grpc`, `http/protobuf` и `http/json` через стандартную переменную окружения `OTEL_EXPORTER_OTLP_PROTOCOL`. Пакет `@opentelemetry/api` — обычная зависимость сервера; SDK, автоинструментация и экспортёры являются необязательными peer-зависимостями, поэтому устанавливать их нужно только для трассировки. Команды установки и полный справочник переменных окружения приведены в [doc/observability.md](doc/observability.md).

Paperclip также поддерживает мониторинг ошибок через Sentry на сервере и в браузере, включаемый по выбору пользователя. Задайте `SENTRY_DSN_FRONTEND` для браузера и `SENTRY_DSN_BACKEND` для сервера. Обе переменные необязательны; устаревшая переменная `SENTRY_DSN` по-прежнему служит резервным значением для любого из компонентов. Поддерживаемая версия серверного SDK — `@sentry/node@10.71.0`; это необязательная peer-зависимость сервера, которую нужно устанавливать только для мониторинга ошибок. Браузерный SDK `@sentry/browser` закреплён на той же версии. Команда установки, настройки конфиденциальности и полный перечень данных, собираемых по умолчанию, приведены в [doc/observability.md](doc/observability.md#sentry-error-monitoring).

## Телеметрия

Paperclip собирает анонимную телеметрию использования, чтобы команда проекта могла понимать, как используют продукт, и улучшать его. Персональные данные, содержимое задач, промпты, пути к файлам и секреты не собираются. Адреса частных репозиториев перед отправкой хешируются с солью, уникальной для каждой установки.

При изменении отправляемых событий телеметрии следуйте [контракту данных телеметрии](packages/shared/src/telemetry/README.md).
Для предлагаемых событий, отправляемых в Paperclip и ещё не включённых в сгенерированный контракт, следуйте [процессу работы с телеметрией](doc/TELEMETRY_WORKFLOW.md).

Телеметрия **включена по умолчанию**. Отключить её можно любым из следующих способов:

| Способ | Как отключить |
| -------------------- | ------------------------------------------------------- |
| Переменная окружения | `PAPERCLIP_TELEMETRY_DISABLED=1` |
| Общепринятая переменная | `DO_NOT_TRACK=1` |
| Среда CI | Автоматически отключается при `CI=true` |
| Файл конфигурации | Укажите `telemetry.enabled: false` в конфигурации Paperclip |
