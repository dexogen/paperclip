## Что изменилось

- Рабочее пространство по умолчанию объединяет чаты с агентами, задачи и входящие. Чат можно закрепить. В карточке задачи видны план агента, вызовы инструментов и изменения файлов.
- Настройки агента можно редактировать в YAML. В чате видно, сколько места осталось в контекстном окне и когда обновятся лимиты провайдера. Историю можно сжать прямо из чата.
- Paperclip Runner умеет продолжать больше прерванных запусков после перезапуска сервера. Локальные Codex и OpenCode по умолчанию еще пять минут держат процесс открытым, чтобы быстрее принять следующее сообщение.

## Перед обновлением

- Подзадача получает свое рабочее пространство. Чтобы передать ей правки из родительской задачи, опубликуйте ветку или влейте изменения через Git.
- При попытке агента вложить задачу глубже второго уровня сервер создаст ее рядом с задачей агента. Если у вас есть скрипт создания задач, проверяйте `parentAdjusted` и используйте `parentId` из ответа. Операторы по-прежнему могут создавать задачи любой вложенности.
- Если инструкции или навыки агента Paperclip Runner меняют статус его текущей задачи через `PATCH /api/issues/{id}`, замените этот вызов на `paperclip_finish` для завершения или `paperclip_block` для блокировки. Пока агент выполняет задачу, API вернет `409 native_run_status_reported_by_finish` при попытке изменить ее статус таким PATCH-запросом.
- Enter отправляет сообщение, Shift+Enter добавляет перенос строки. Прежнее сочетание Ctrl+Enter или Cmd+Enter можно вернуть в экспериментальных настройках.
- Встроенное подключение Google Workspace по умолчанию выключено. Если вы его используете, включите Google Workspace в экспериментальных настройках.
- Проверьте переменные окружения агентов `pi_local`. Если команда рассчитывает на переменную сервера `PAPERCLIP_*`, явно задайте ее в настройках адаптера. Paperclip по-прежнему передает параметры подключения к API и переменные текущего запуска.
- Если локальный Codex или OpenCode должен завершать процесс сразу после работы, выберите "После каждого запуска" в настройках жизненного цикла Runner.

## Хранилище и откат

Если обновляетесь с версии до миграции `0415`, сделайте согласованный бэкап PostgreSQL и файлового или объектного хранилища. После миграции Paperclip в фоне переносит туда содержимое пакетов навыков. После переноса для отката на старую версию потребуется вернуть содержимое пакетов в БД. Если при поэтапном обновлении одновременно работают разные версии, на это время задайте `PAPERCLIP_SKILL_PACKAGE_STORAGE_ENABLED=false` на всех процессах Paperclip.
